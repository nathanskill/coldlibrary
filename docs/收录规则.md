# 资料室收录规则（GitHub 开放资源）

2026-11-01 起施行。资料室（The Reference Room，`/reference`）收 GitHub 上和本馆类别相关、真正有用、可以合法收录的开放资源。管线：`tools/reference/collect.mjs`；数据：`catalog/reference/`。

## 1. 收什么

| 类别 | 收 | 例子 |
|---|---|---|
| 文学 literature | 公版全文、诗词库、文学语料、戏剧和小说语料库 | chinese-poetry、Perseus 希腊拉丁文本、青空文库、DraCor |
| 信仰 faith | 公版经典及其译本、经文数据、带标注的原文、辞典 | CBETA、SuttaCentral、Sefaria、开放的圣经与古兰经数据 |
| 历史 history | 史料、年表、历史地图、地名辞典、开放数据集、铭文纸草 | historical-basemaps、Pleiades、papyri.info |
| 美学 aesthetics | 博物馆开放馆藏数据和接口、艺术数据集、开源字体、汉字字形、传统色 | 大都会、MoMA、Tate 开放数据；思源宋体、霞鹜文楷 |
| 音乐 music | 开放的专辑和曲目元数据、乐谱语料、乐理和记谱工具 | MusicBrainz、OpenScore、The Session、music21 |
| 工具 tools | 做上面这些用得上的工具：古籍 OCR、TEI、校勘、IIIF 看图、繁简转换、历法 | Tesseract、kraken、OpenCC、Mirador |

每条再标一个形态：全文 text · 数据集 dataset · 接口 api · 字体 font · 工具 tool · 书单 list。

## 2. 许可证

- 每条都记 GitHub 识别出的许可证（SPDX 编号），对外分五档：
  - **公有领域**：CC0、Unlicense 等；
  - **宽松**：MIT、Apache、BSD、CC BY、OFL 等；
  - **相同方式共享**：GPL、AGPL、LGPL、CC BY-SA、ODbL 等；
  - **受限或自定**：非商业、禁止演绎、仓库自己写的条款、GitHub 认不出的；
  - **未声明**：没有许可证文件，按保留所有权利对待。
- 本馆不搬运仓库内容。每条只存：名称、链接、馆员写的一句话介绍（中英）、仓库自述（GitHub 的一行描述原文）、许可证、星数、最近更新、主题标签。
- 公有领域和宽松许可证的可以收**摘录**（几行样例，注明出处和许可证）；相同方式共享的摘录按原许可证标明；受限、自定和未声明的**只收名称、一句话和链接**。
- 许可证是仓库自己的声明。代码和数据可能各有条款（例如代码 MIT、数据另有约定），以仓库说明为准；页面上写明这一点。
- 馆员写的一句话介绍和本页其他文字是 CC0，和开架书库一样。

## 3. 收录标准

收：

- 有实际内容：文本、数据、字形或能用的程序，不是空仓库、模板、作业、只有 README 的占位。
- 近两年有人维护（默认分支两年内有提交）；或者本身是定稿的文本、数据、字体（已归档或星数 ≥100，内容完整）。
- 星数只作参考：小而准的专门资料（例如一部古籍的校勘本）照收。

不收：

- 搬运盗版：未授权的电子书和扫描件、歌词、音频、影视、有版权的辞书整本数据。
- 爬别家网站的爬虫和下载器，绕过付费或限制的工具。
- 商业广告、推广、付费墙后面才有内容的；加密货币、成人内容。
- 政治宣传和关键词堆砌的垃圾仓库（搜索里很常见，管线有屏蔽词）。
- fork 和镜像（收原仓库）。
- 本馆维护者自己的项目；任何要求付钱、交钥匙或密码的东西（本馆不收钱、不保管钥匙）。

拿不准的不上架：留在队列，或写明原因放进 `_rejected.json`。

## 4. 排队用的分数

只决定审核顺序，**不对外显示，也不是馆员评分**（资料室的条目不打十分制分数）：
星数对数（最多 40）＋最近更新（半年内 20、一年内 15、两年内 10、定稿 6）＋许可证（公版和宽松 15、相同方式共享 12、受限 6、自定 5、未声明 0）＋被几个来源提到（每个 6，最多 18）＋种子名单 10。

## 5. 一句话介绍怎么写

- 中文不超过 40 字（含标点，夹在中间的英文字母按半个字算），英文不超过 20 个词；说它装了什么、能拿来做什么。
- 写事实，不夸，不用感叹号，不抄 README 和别人的介绍。
- 不提本馆创办人和任何私人。

## 6. 每周流程

```bash
node tools/reference/collect.mjs weekly   # 抓候选、取元数据、刷新已上架条目、生成队列
# 审 catalog/reference/_queue.json：decision 填 accept（并写 note.en / note.zh，核对 cat、kind）或 reject（写 reason）
node tools/reference/collect.mjs apply    # 上架和拒收各归各位，队列只留没决定的
node site/build.mjs                       # 构建，确认没有警告
```

- 令牌只从环境变量 `GITHUB_TOKEN` 或 `gh auth token` 当场读取，不写进仓库、日志和缓存。
- 搜索接口每分钟 30 次，脚本每次间隔 2.3 秒；碰到限速自动等。
- 已上架的条目每周刷新：仓库没了标 `gone`（页面不再显示），许可证变了记下旧值 `license_was` 等馆员看。
- 入口在 `catalog/reference/sources.json`：awesome 书单、GitHub 主题、关键词搜索、种子名单、屏蔽词。加新入口改这里。
