## 引言

本文档为构成 Python 主发行版标准库的 Python 代码给出编码约定。关于 Python 的 C 语言实现中 C 代码的风格准则，请参阅与之配套的信息类 PEP。

本文档与 PEP 257（文档字符串约定）改编自 Guido 最初的那篇《Python 风格指南》短文，并吸收了 Barry 的风格指南中的一些内容。

随着新的约定被总结出来、旧的约定因语言本身的变化而过时，这份风格指南也在不断演进。

许多项目有自己的编码风格准则。如有冲突，以该项目自己的准则为准。

## 愚蠢的一致性是狭隘心灵的妖怪

Guido 的一个关键洞见是：代码被阅读的次数远多于被编写的次数。这里给出的准则，旨在提高代码的可读性，并让形形色色的 Python 代码保持一致。正如 PEP 20 所说：“可读性很重要。”

风格指南关乎一致性。与本指南保持一致很重要；在一个项目之内保持一致更重要；在一个模块或函数之内保持一致最重要。

然而，要懂得什么时候不必一致——有时风格指南的建议就是不适用。拿不准的时候，运用你自己最好的判断。看看别的例子，决定怎样最好看。也别犹豫，开口问吧！

尤其是：不要仅仅为了符合本 PEP 而破坏向后兼容！

忽略某条准则的其他正当理由还有：

1. 应用这条准则会让代码更难读，哪怕对一个习惯了遵循本 PEP 的代码的人来说也是如此。

2. 为了与周围同样违反这条准则的代码保持一致（也许出于历史原因）——不过这也是一个替别人收拾烂摊子的机会（正宗的 XP 风格）。

3. 相关代码早于这条准则出现，而且也没有别的理由去修改那段代码。

4. 代码需要兼容较老版本的 Python，而那些版本不支持风格指南所推荐的特性。
