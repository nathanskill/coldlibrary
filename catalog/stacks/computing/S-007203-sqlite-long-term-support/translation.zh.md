开发者们打算一直支持 SQLite 到 2050 年。

在写下这些话的时候，2050 年还在 25 年之后。没有人知道这段时间里会发生什么，我们也不能绝对保证 SQLite 到那么远的将来仍然可行、仍然有用。但我们可以保证这一点：我们按照将一直支持 SQLite 到 2050 年来做计划。这种长远的眼光，在一些重要的方面影响着我们的决定。

**跨平台的代码** → SQLite 可以在任何具备 8 位字节、二进制补码 32 位和 64 位整数以及一个 C 编译器的平台上运行。它在当今所有流行的 CPU 和操作系统上都经过积极的测试。SQLite 代码和文件格式极高的可移植性，将帮助它在未来的平台上继续可用。

**稳定的、跨平台的数据库文件** → SQLite 数据库文件在 32 位、64 位、大端和小端平台上逐位相同。你可以把一个 SQLite 数据库文件从一个系统复制到另一个系统，而不必对数据库做任何转换。此外，文件格式有详尽的文档，而且是稳定的。今天创建的数据库文件，几十年后的 SQLite 版本仍然能够读写。

**航空级的测试** → 每一条机器码分支指令都在两个方向上经过测试。测试多次。在多个平台上，用多种编译器。这有助于让代码在未来的迁移中保持稳健。高强度的测试还意味着，新的开发者可以对 SQLite 做试验性的改进，而且只要原有的测试全部通过，就可以相当有把握地认为这项改进没有破坏原有的东西。

**全面而详细的文档** → SQLite 有坦率的、对开发者友好的开源文档。文档由程序员写，为程序员写。全面的文档帮助新的开发者很快熟悉 SQLite。

**大量注释的源代码** → SQLite 的源代码有超过 35% 是注释。不是套话式的注释，而是有用的注释，解释变量和对象的含义，以及方法和过程的意图。代码的设计目标，是让新的程序员能够读懂，并能在几十年的时间跨度里加以维护。

**灾难预案** → SQLite 源代码历史的每一个字节都受到密码学保护，并自动复制到多台地理上相互分隔的服务器上，这些服务器位于不同公司所有的数据中心里。世界各地的私人服务器上还有成千上万份额外的克隆。SQLite 的主要开发者住在世界的不同地区。SQLite 能够在一场大陆级的灾难中幸存下来。

**老派** → 没有人能完全不受潮流和时尚的影响，但 SQLite 的开发者们努力避免被卷进最新的编程风尚。我们的目标是写出不会过时的代码，让还没有出生的程序员也能阅读、理解和维护。

除了“支持” SQLite 到 2050 年之外，开发者们还承诺让 SQLite 的 C 语言 API 和磁盘格式保持完全的向后兼容。这意味着今天编写的使用 SQLite 的应用程序，应当能够链接并使用几十年后发布的 SQLite 新版本。

我们的目标，是让你今天存进 SQLite 的内容，对你的孙辈来说也和对你一样容易取用。

**2018-05-31 更新：**我们长期支持 SQLite 的目标，显然引起了美国国会图书馆保存专家的注意，他们已把 SQLite 列为保存数字内容的推荐存储格式。
